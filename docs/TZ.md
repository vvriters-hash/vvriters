## 1. Продукт в одном абзаце

Веб-сервис по подписке для креаторов коротких видео (Reels, YouTube Shorts, TikTok). Пользователь загружает бриф в любом виде: текст, файл или голосовое. Сервис выделяет из него задачу, находит 10–30 топовых роликов в нише, разбирает каждый (цифры, хук, структура, комментарии, гипотеза «почему залетел»), генерирует идеи в формате логлайнов, помогает написать сценарии в табличном формате и строит раскадровку картинками. Всё это в одном интерфейсе, с выгрузкой отчётов и сценариев в Google Docs / DOCX / PDF с брендингом. На бесплатном тарифе выгрузка идёт с водяным знаком.

## 2. Целевая аудитория и роли

**Основной пользователь:** креатор, сценарист или SMM-щик, который делает видео для соцсетей (для себя или для клиентов). Типичная нагрузка: 4–5 проектов в месяц по ~10 роликов в каждом.

| Роль | Права |
|---|---|
| **Владелец** рабочего пространства | Всё + оплата, участники, брендинг |
| **Редактор** | Создаёт и редактирует проекты |
| **Клиент (гость по ссылке)** | Заполняет бриф; смотрит, комментирует и согласовывает отчёт, идеи и сценарии. Без регистрации или с упрощённой регистрацией |
| **Админ сервиса** (мы) | Пользователи, тарифы, лимиты, мониторинг затрат, модерация |

## 4. Функциональные требования

### 4.1 Аккаунт, рабочее пространство, проекты [MVP]

- Регистрация: email + пароль, Google, Telegram Login.
- Одно рабочее пространство на пользователя по умолчанию. Тариф «Про» даёт несколько мест (участников).
- Список проектов: название, клиент, ниша, статус этапа, дата, кто работал.
- Проект — главная сущность. Внутри вкладки: **Ресёрч · Аналитика · Идеи · Сценарии · Экспорт**.
- Во вкладку можно перейти, только если пройдена предыдущая (мягкое правило: можно пропустить с предупреждением).
- Язык интерфейса RU/EN/ES [MVP: RU, MVP+: EN/ES]. Язык проекта (на каком языке писать результаты) задаётся отдельно от языка интерфейса.

### 4.2 Модуль 1 — Ресёрч (бриф) [MVP]

**Вход** (всё, что угодно, в любом сочетании):
- Текст в поле ввода.
- Файлы: PDF, DOCX, TXT, MD, изображения (скриншоты переписок), таблицы.
- Аудио/видео: голосовые (OGG/OPUS из Telegram, M4A, MP3, WAV), видеофайлы. Лимит до 60 минут на файл и до 500 МБ.
- Ссылки: сайт клиента, профиль в соцсети, ролики-референсы.
- **Ссылка для клиента**: клиент сам заполняет бриф через диалог с агентом, без регистрации.

**Обработка:**
1. Расшифровка аудио и видео (распознавание речи, язык определяется автоматически).
2. Извлечение текста из документов и изображений (OCR).
3. ИИ раскладывает всё по полям шаблона брифа (п. 4.2.1).
4. **Агент задаёт уточняющие вопросы**, если важные поля пустые или противоречат друг другу. Формат — чат справа от брифа. Вопросы приоритизированы: сначала критичные (цель, ЦА, площадка).
5. Полнота брифа показывается в процентах. Бриф можно утвердить и при неполноте, с предупреждением.

**Выход:** структурированный бриф (редактируемый) + «ядро запроса»: **ниша, цель, ЦА, площадки, формат** — отсюда стартует аналитика.

#### 4.2.1 Шаблон брифа (предложено)

| Блок | Поля |
|---|---|
| Клиент | Бренд/персона, продукт или услуга, сайт и соцсети, ниша, конкуренты |
| Цель | Основная цель (охват / подписчики / продажи / лиды / узнаваемость / прогрев), KPI, ключевое сообщение, CTA |
| Аудитория | Портрет ЦА (пол, возраст, гео, интересы, боли), на каком языке говорим |
| Формат | Площадки, количество роликов, хронометраж, вертикаль/горизонталь, рубрики |
| Стиль | Тон (юмор / экспертно / эмоционально…), референсы «нравится» и «не нравится», бренд-гайд |
| Производство | Кто в кадре (эксперт, актёры, UGC, без лица), локации, реквизит, бюджет, монтаж своими силами или нет |
| Ограничения | Запретные темы, юридические ограничения (реклама, медицина, финансы), обязательные элементы |
| Сроки | Дедлайны по этапам |

### 4.3 Модуль 2 — Аналитика [MVP]

#### 4.3.1 Подбор роликов
- Пользователь выбирает число роликов: **10 / 20 / 30** и площадки: **TikTok, Reels, YouTube Shorts** (любое сочетание).
- Агент сам строит поисковую стратегию по брифу: ключевые слова и хэштеги на языке аудитории, похожие аккаунты, смежные ниши. Стратегию видно и можно поправить до запуска.
- Пользователь может **добавить свои ссылки** (они анализируются обязательно) и **исключить** ролики.
- **Критерии «топового» ролика (предложено):**
  - период — последние 90 дней (настраивается: 30 / 90 / 180 / 365);
  - **коэффициент выброса** = просмотры ролика ÷ медиана просмотров последних 20 роликов автора; приоритет у роликов с коэффициентом ≥ 3;
  - минимальные просмотры: настраиваются, по умолчанию 100 тыс. для широкой ниши и 20 тыс. для узкой (агент решает по размеру ниши);
  - вовлечённость (ER) = (лайки + комментарии + репосты + сохранения) ÷ просмотры;
  - релевантность брифу — оценка ИИ.
- Кандидатов берём в 2–3 раза больше, чем нужно, ранжируем и показываем пользователю отобранные ролики. Можно утвердить набор сразу или заменить часть роликов.

#### 4.3.2 Разбор каждого ролика
Требования к исполнению:
- анализ идёт в фоне: **30 роликов ≤ 10 минут** (p95), ≤ 5 минут для 10 роликов;
- прогресс виден в реальном времени (ролик за роликом);
- в конце уведомление: в приложении, по email и в Telegram-боте;
- если ролик недоступен (удалён или закрыт), он помечается, и предлагается замена.

**Карточка ролика (предложено):**

| Раздел | Содержание |
|---|---|
| Паспорт | Ссылка, площадка, автор, подписчики автора, дата, длительность, превью |
| Цифры | Просмотры, лайки, комментарии, репосты, сохранения (если доступны), ER, коэффициент выброса, звук/музыка (трендовый или нет) |
| Хук (0–3 с) | Что в кадре, текст на экране, первая фраза, тип хука (вопрос / провокация / результат в начале / POV / …) |
| Структура | Таймлайн сегментов: хук → завязка → развитие → кульминация → CTA, с таймкодами |
| Формат и монтаж | Формат (говорящая голова, скринкаст, сценка, туториал, POV, до/после…), темп (склеек в минуту), субтитры, графика, музыка |
| Текст | Расшифровка речи + текст на экране |
| Комментарии | Разбор до 200 комментариев: тональность (%), ключевые темы, **вопросы зрителей**, возражения, яркие цитаты |
| Почему залетел | 3–5 гипотез с уровнем уверенности и ссылкой на доказательства (таймкод, цифра, цитата из комментариев) |
| Что взять себе | Как приём применим к нашему брифу |
| Оценка | Релевантность брифу 1–10 |

#### 4.3.3 Сводная аналитика по подборке
- Общие закономерности: форматы, хуки, длительность, темы, которые чаще всего встречаются у топовых роликов.
- Что зрители спрашивают и о чём спорят (это точки для контента).
- Незанятые ниши и углы (о чём не снимают, но спрашивают).
- Рекомендации по формату и контент-плану.
- Таблица всех роликов с сортировкой и фильтрами.

#### 4.3.4 Отчёт для клиента
- Собирается из брифа, сводки и выбранных карточек роликов.
- **Редактируется** прямо в сервисе (текстовый редактор с блоками), можно удалять и перемещать блоки.
- Брендинг: логотип, цвета, название студии в колонтитуле (п. 4.7).
- Выгрузка: Google Docs (основной формат), DOCX, PDF, веб-ссылка на просмотр.

### 4.4 Модуль 3 — Идеи (логлайны) [v2]

- Генерация пачки идей: **5 / 10 / 20** за раз (выбирает пользователь).
- Каждая идея: **логлайн** (1–2 предложения) + формат + хук + на какой ролик или инсайт из аналитики опирается + оценка по брифу.
- Действия с идеей: ★ в избранное, ✎ редактировать, ↻ «ещё похожих», ✕ отклонить с причиной (агент учитывает причину при следующей генерации).
- Режимы: «широкий поиск» (разные форматы) / «в стиле конкретного ролика» / «рубрика» (серия роликов).
- Клиент может комментировать и согласовывать идеи по ссылке.
- Выгрузка списка идей в документ.

### 4.5 Модуль 4 — Сценарий [v2, раскадровка — v3]

#### 4.5.1 Таблица сценария
Формат основан на вашем реальном сценарии (`reels_yandex.browser`).

| № | Что в кадре | Референс | Графика | Звуки / реплики | Хрон (с) | Раскадровка [v3] |
|---|---|---|---|---|---|---|
| 1 | Средний план. Девушка за ноутбуком, звонит будильник… | ссылки / картинки | текст на экране | \*голос девушки\* «Да кто вообще придумал будильники?» | 2 | 🖼 |

- Набор колонок по умолчанию — как выше; колонки можно добавлять, скрывать и переименовывать (шаблоны колонок на уровне рабочего пространства).
- Строки можно добавлять, удалять, перетаскивать и объединять. В ячейках форматированный текст и ссылки; в колонку «Референс» можно вставить картинку или ссылку с превью.
- **Хронометраж суммируется автоматически** (итог внизу, например «1:04»), а если превышен целевой хронометраж из брифа, это подсвечивается.
- Шапка сценария: название, проект, логлайн, площадка, целевой хронометраж, версия, статус.

#### 4.5.2 Помощь ИИ при написании
- «Написать сценарий по логлайну» → заполненная таблица целиком.
- Действия над строкой или выделением: переписать, сократить, усилить хук, сделать смешнее, адаптировать под другую площадку, перевести.
- Проверка сценария по **чек-листу качества** (предложено: хук в первые 2 с, одна мысль на ролик, CTA, хронометраж, соответствие брифу, нет запретных тем). Результат — замечания на полях.
- Версии: история изменений, сравнение версий, откат.

#### 4.5.3 Раскадровка [v3]
- Картинки генерируются **только после утверждения текста** (кнопка «Утвердить текст» → «Сгенерировать раскадровку»).
- Стиль — **эскиз-раскадровка** (предложено: единый набросочный стиль, вертикаль 9:16). Стиль задаётся на проект, чтобы кадры были единообразными.
- Промпт для каждого кадра собирается автоматически из колонок «Что в кадре» и «Графика» + описания персонажей проекта (для единообразия героев).
- Перегенерация отдельного кадра, правка промпта вручную, загрузка своей картинки вместо сгенерированной.
- Генерация картинок — только GPT Image (OpenAI).

#### 4.5.4 Совместная работа [v2]
- Одновременное редактирование несколькими людьми (как в Google Docs), курсоры участников.
- Комментарии к ячейкам и строкам, упоминания, статус «Согласовано клиентом».
- Доступ клиенту по ссылке: просмотр + комментарии + кнопка «Согласовать».

### 4.6 Модуль 5 — Экспорт [MVP для отчёта, v2 для сценария]

| Формат | Что выгружается | Примечания |
|---|---|---|
| **Google Docs** (основной) | Отчёт, идеи, сценарий-таблица | Создаётся в Google Drive пользователя (OAuth). Колонтитул с брендингом |
| DOCX | То же | Колонтитул, водяной знак на бесплатном тарифе |
| PDF | То же + раскадровка | Водяной знак на бесплатном тарифе |
| Веб-ссылка | Просмотр в браузере | Для клиента, можно отозвать |

**Водяной знак и колонтитул:**
- В каждом экспорте есть колонтитул: логотип и название студии пользователя, проект, дата, номер страницы.
- **Бесплатный тариф:** водяной знак «Сделано в VVriters Studio» по диагонали (PDF/DOCX) + строка в колонтитуле.
- ⚠️ Ограничение: в редактируемом формате (Google Docs, DOCX) водяной знак технически можно удалить. Google Docs API, насколько известно, не умеет ставить водяной знак; в DOCX он удаляется в редакторе. Поэтому **(предложено)** на бесплатном тарифе доступен только PDF с водяным знаком, а редактируемые форматы — на платных. Проверить в Фазе 0.

### 4.7 Брендинг [MVP]
- В настройках рабочего пространства: логотип, название, основной цвет, контакты для колонтитула.
- Применяется ко всем экспортам и к веб-ссылкам для клиента.
- White-label (без упоминания VVriters) — только на тарифе «Про».

### 4.8 Модуль 6 — Тренды [v3]
- Отслеживание: ниши (набор ключевых слов), хэштеги, аккаунты конкурентов, трендовые звуки.
- Регулярный сбор (раз в сутки), дайджест в приложении, на почту и в Telegram: что выросло, новые ролики-выбросы, новые темы.
- Графики динамики по хэштегу или нише: число роликов, суммарные просмотры, средний ER.
- Из дайджеста ролик одним кликом добавляется в аналитику проекта.

### 4.9 Модуль 7 — Поиск заказов [v4]
Развитие вашего Telegram-парсера.

- Источники: Telegram-чаты и каналы с заказами (список настраивается). Работает через пользовательский аккаунт Telegram (MTProto) — так видны чаты без бота.
- Для каждого сообщения:
  1. **Фильтр:** это заказ или нет (реклама, резюме, спам отсекаются).
  2. **Дедупликация:** один заказ, опубликованный в нескольких чатах, склеивается.
  3. **Карточка лида (предложено):** суть задачи в 1–2 строки, тип работы (сценарий / съёмка / монтаж / SMM…), ниша, площадка, объём, бюджет (если указан) или оценка, срок, контакт, ссылка на исходное сообщение, **оценка «стоит ли браться» 1–10** с причиной (соответствие профилю, бюджет, адекватность).
  4. **Черновик первого сообщения** + 3–5 уточняющих вопросов, с которых можно начать общение (в стиле студии).
- Выход: Telegram-бот (карточка + кнопки «Взять в работу» / «Не интересно» / «Скопировать отклик») и Google-таблица со статусами.
- Кнопка «Создать проект» — лид сразу превращается в проект с черновиком брифа.

### 4.10 Модуль 8 — Команда и подрядчики [v4]
Для студий, которые работают с внештатными сценаристами. Состав (предложено):
- **Подрядчики:** карточка (роль, ставки, статус самозанятого с проверкой через сервис ФНС, реквизиты), история работ.
- **Задачи:** выдать подрядчику сценарий из проекта с дедлайном, сдача работы в сервисе.
- **«Агент подрядчиков»** — ИИ-помощник, который:
  - собирает задание для подрядчика из брифа и аналитики;
  - проверяет сданную работу по чек-листу стандарта качества и пишет замечания;
  - напоминает о дедлайнах;
  - собирает документы для оплаты (акт и чек самозанятого).
- **Документы:** шаблоны договора ГПХ с самозанятым, акта, задания; генерация из карточки подрядчика.
- **Стандарты качества:** редактируемый документ студии (оформление, требования к сценарию, чек-лист) — используется и агентом проверки.
- **Общий доступ к нейросетям:** все подрядчики работают через сервис с оплатой с аккаунта студии, личные подписки не нужны.

Краткая памятка по самозанятым (НПД) — в [DECISIONS.md](DECISIONS.md#памятка-самозанятые).

### 4.11 Оплата и тарифы [MVP]
- Фиксированная ежемесячная подписка (годовая — со скидкой), тарифы и лимиты — в [ECONOMICS.md](ECONOMICS.md).
- Внутри тарифа действуют **кредиты**: у каждого действия своя цена в кредитах (анализ ролика, генерация сценария, картинка). Пользователь видит остаток. Это страхует от убыточных пользователей.
- Докупка пакетов кредитов.
- Юрлицо — Грузия. Платёжная система: международный merchant of record (Paddle или аналог — платёжка сама платит налоги с продаж по странам) + запасной вариант — эквайринг грузинского банка. Цены показываются в рублях (для RU-интерфейса) и в долларах или евро, списание — в валюте платёжки.
- Карты российских банков не принимаются (ограничение юрлица). Приём оплаты из РФ через платёжных агентов — отдельное решение после консультации юриста (см. DECISIONS §2).
- Платёжка подключается через общий интерфейс в коде, чтобы её можно было заменить или добавить вторую.
- Пробный период: бесплатный тариф без ограничения по времени, но с малыми лимитами.

### 4.12 Уведомления [MVP]
- В приложении, email, Telegram-бот.
- События: аналитика готова, клиент оставил комментарий или согласовал, заканчиваются кредиты, списание подписки, (v4) новые лиды.

### 4.13 Telegram-бот [MVP]
Второй вход в сервис, для работы с телефона.
- Привязка к аккаунту в один клик (Telegram Login или код из настроек).
- **Пересылаешь боту голосовое, текст, файл или ссылку от клиента** → бот спрашивает «В какой проект?» (новый или один из последних) → материалы попадают во вкладку Ресёрч, запускается разбор брифа.
- Уточняющие вопросы агента по брифу приходят в бот, отвечать можно голосом или текстом.
- Кнопка «Запустить аналитику» (10 / 20 / 30 роликов) прямо из бота, когда бриф заполнен.
- Уведомления: аналитика готова (со ссылкой на отчёт и краткой сводкой в 3–5 строк), клиент прокомментировал или согласовал, заканчиваются кредиты.
- Пересылка ссылки на ролик → «Добавить в проект X» или «Разобрать отдельно» (тратит кредиты).
- [v4] Тот же бот присылает лиды из модуля 7.

### 7.2 Источники данных о роликах
Вывод по вопросу 8: **официальных API недостаточно** (TikTok Research API — только для исследователей, Instagram Graph API — только для своих бизнес-аккаунтов и ограниченного поиска по хэштегам). Схема:

- В коде делаем **слой-абстракцию `DataProvider`** с единым интерфейсом: `search`, `getVideo`, `getComments`, `getAuthorVideos`, `getDownloadUrl`. Провайдеры подключаются как адаптеры.
- **YouTube Shorts** → официальный YouTube Data API v3 (бесплатно, квота 10 000 единиц в день, поиск стоит 100 единиц; при росте — заявка на увеличение квоты) + агрегатор для недостающего.
- **TikTok и Reels** → сторонний агрегатор данных. Для MVP — ScrapeCreators (оплата за запросы, без абонплаты) с резервным провайдером (Apify или EnsembleData). Сравнение — в ECONOMICS.
- Собственный парсинг — только если объёмы вырастут настолько, что агрегатор станет дорогим (не раньше 3–5 тыс. проектов в месяц).
- Риски: условия площадок запрещают сбор данных; провайдеры могут ломаться и менять цены. Смягчение: два провайдера, кэширование (ролик, разобранный для одного пользователя, повторно не качается 7 дней), видео удаляются после анализа.

### 7.3 Конвейер аналитики (фоновая задача)
1. `plan` — ИИ строит поисковую стратегию по брифу.
2. `search` — параллельные запросы к провайдерам → кандидаты (×2–3 от нужного числа).
3. `rank` — метрики + коэффициент выброса + релевантность (дешёвая модель) → топ-N → подтверждение пользователем (или автоподтверждение).
4. По каждому ролику параллельно (лимит ~10 на задачу):
   `fetch` метаданных и комментариев → `download` видео → `ffmpeg` (6–10 ключевых кадров + аудио) → `transcribe` → `analyze` (Claude: кадры + расшифровка + комментарии + метрики → JSON по схеме карточки).
5. `synthesize` — сводная аналитика по всем карточкам.
6. `notify`.

Каждый шаг идемпотентен, результат сохраняется сразу — упавший ролик не валит всю задачу.

### 7.4 Модель данных (основные сущности)
```
User ─< Membership >─ Workspace ─< Subscription, CreditLedger, BrandKit
Workspace ─< Project
Project ─ Brief ─< SourceFile (файл, расшифровка, OCR)
Project ─< AnalysisRun ─< VideoCandidate
Video (кэш по платформе + id) ─< VideoAnalysis, CommentSample
AnalysisRun ─ Synthesis ; Project ─< Report (документ Yjs)
Project ─< IdeaBatch ─< Logline
Project ─< Script ─< ScriptVersion ; Script ─< ScriptRow ─< StoryboardImage
Project ─< Export ; Project ─< ShareLink ─< Comment

Workspace ─< LeadSource ─< Lead                                  [v4]
Workspace ─< Contractor ─< Task, Document                        [v4]
```

`UsageEvent` фиксирует **каждый** платный вызов (провайдер, модель, токены, секунды, стоимость в $) — на этом строятся кредиты, контроль маржи и тарифы.

### 7.5 Промпты и качество ИИ
- Промпты хранятся версионированно (в репозитории), у каждой карточки записано, какой версией промпта она сделана.
- Структурированный вывод по JSON-схемам.
- **Набор эталонных проверок (eval):** 20–30 реальных брифов и роликов с эталонными разборами. Каждое изменение промпта или модели прогоняется по ним до выката.
- Кэширование промптов (prompt caching) для длинного общего контекста проекта — экономия на входных токенах.

## 8. Интерфейс (экраны)

1. **Вход / регистрация**, онбординг (роль, ниша, язык, загрузка логотипа).
2. **Проекты** — список и карточки, кнопка «Новый проект».
3. **Проект → Ресёрч:** слева загрузка материалов, по центру бриф по полям, справа чат с агентом. Внизу кнопка «Утвердить бриф → Аналитика».
4. **Проект → Аналитика:** настройки подбора (площадки, число роликов, период) → стратегия поиска → прогресс → сетка карточек роликов + сводка + таблица. Кнопка «Собрать отчёт».
5. **Отчёт:** редактор документа, панель блоков, кнопка «Экспорт».
6. **Проект → Идеи:** лента карточек-логлайнов, фильтры, избранное, кнопки генерации.
7. **Проект → Сценарии:** список сценариев → редактор-таблица, ИИ-панель справа, итоговый хронометраж, версии, комментарии.
8. **Раскадровка:** та же таблица с колонкой картинок + режим «доска» (кадры плиткой).
9. **Экспорт:** выбор документов и формата, предпросмотр колонтитула и водяного знака.
10. **Публичная ссылка для клиента:** бриф (заполнение) / отчёт / сценарий (просмотр, комментарии, согласование).
11. **Тренды** [v3], **Лиды** [v4], **Команда** [v4].
12. **Настройки:** профиль, рабочее пространство, участники, брендинг, интеграции (Google, Telegram), язык.
13. **Тарифы и оплата**, остаток кредитов, история.
14. **Админка.**

Дизайн: тёмная тема в фирменном стиле VVriters (как в текущем калькуляторе: чёрный фон, бирюзовый акцент `#00bcd4`) + светлая тема. Адаптив: полноценная работа на десктопе, просмотр и комментирование с телефона.

## 9. Критерии приёмки MVP

1. Пользователь регистрируется, оплачивает тариф (тестовый платёж) и видит кредиты.
2. Загружает голосовое на 5 минут + PDF → получает заполненный бриф и уточняющие вопросы от агента.
3. Запускает аналитику на 30 роликов из TikTok + Reels + Shorts → в течение 10 минут получает 30 карточек по формату п. 4.3.2 и сводку.
4. Добавляет 2 свои ссылки — они проанализированы.
5. Собирает отчёт, редактирует, выгружает в Google Docs с логотипом в колонтитуле; на бесплатном тарифе — PDF с водяным знаком.
6. Получает уведомление в Telegram о готовности аналитики.
7. В админке видно себестоимость этого проекта в $ по каждому вызову API.
8. Средняя себестоимость проекта укладывается в модель из ECONOMICS (±30 %).
